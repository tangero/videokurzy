Testování pluginů a volné okno pro každý panel — novinky Claude Code Week 37

Týden 37 přinesl v rozsahu verzí v2.1.263 až v2.1.269 dvě změny, které rozšiřují schopnosti nástroje. Jedna cílí na tvůrce pluginů: nový podpříkaz pro automatizované testování. Druhá řeší každodenní ergonomii v desktopové aplikaci: panely nyní lze vytrhnout do vlastních oken. Vedle toho přibylo zhruba deset drobnějších úprav, které zpřesňují chování auto modu, rozhraní VS Code a několika dalších oblastí.

Přehled větších změn

  • Testování pluginů příkazem claude plugin eval (v2.1.269)
  • Volná okna pro panely v desktopové aplikaci (Desktop)

Velké změny

Testování pluginů příkazem claude plugin eval

Příkaz claude plugin eval spustí váš plugin proti připravené sadě testovacích případů, ohodnotí výsledky a — pokud nezakážete výchozí chování — provede každý případ znovu bez pluginu. Výsledky obou běhů pak lze porovnat a přesně vidět, jaký přínos plugin má.

Pro první kroky slouží claude plugin eval init: interaktivně se zeptá, jak má správný výsledek vypadat, navrhne testovací případy i kontrolní kritéria, jednou sadu spustí a zapíše výsledné soubory. Každý běh a každá kontrola, při níž druhý model posuzuje odpověď, je skutečné volání modelu na vašem účtu — je proto vhodné kalkulovat s náklady při opakovaném spouštění v CI.

Interpretace: Doposud neexistoval standardizovaný způsob, jak ověřit, že plugin dělá to, co má. Automatizovaná testovací sada snižuje riziko regresí při úpravách pluginu a usnadňuje jejich sdílení — příjemce může spustit testy a okamžitě vidět, zda plugin na jeho konfiguraci funguje.

Dokumentace: Plugin evals — v2.1.269

Volná okna pro panely v desktopové aplikaci

V desktopové aplikaci Claude Code lze nyní libovolný panel — diff, terminál nebo jiný — přetáhnout do samostatného okna. Panel tak lze umístit na druhý monitor, zatímco Claude pokračuje v práci v hlavním okně. Po skončení práce stačí panel zpět ukotit.

Interpretace: Uživatelé s více monitory mohli doposud rozložení pracovní plochy přizpůsobit jen omezeně. Možnost přesunout diff nebo terminál na vedlejší obrazovku odpovídá způsobu práce, na který jsou vývojáři zvyklí z jiných nástrojů — a při delších bězích agenta to přináší znatelně lepší přehlednost.

Dokumentace: Arrange your workspace — Desktop

Drobnosti

  • Nastavení maxEffortLevel lze uvést na nejvyšší úrovni nebo per-model pod modelSettings; omezuje maximální úroveň úsilí na všech poskytovatelích, včetně Amazon Bedrock, Google Cloud Agent Platform a Microsoft Foundry — vyšší hodnota se zastropuje na nastavené hranici.
  • Parametr --plugin-dir přijme složku s pluginy a načte každou bezprostřední podsložku s manifestem jako samostatný plugin pro dané sezení.
  • Pokud WebFetch nestáhne stránku do pěti minut, fetch selže s chybou o překročení lhůty místo toho, aby visel; proměnná CLAUDE_CODE_WEBFETCH_DEADLINE_MS lhůtu upravuje, hodnota 0 limit odstraní.
  • Přepínač --json u příkazů claude plugin install, uninstall, update, enable a disable vypíše výsledek jako jeden objekt JSON na poslední řádek stdout.
  • Když klasifikátor auto modu zablokuje akci, důvod předaný Claudovi obvykle uvádí název pravidla, které akci zachytilo, například [Data Exfiltration] — snazší ladění pravidel povolení.
  • Zadáte-li / uprostřed promptu, zobrazí se seznam všech shodujících se příkazů místo jediného návrhu; v celoobrazovkovém zobrazení se seznam otevírá průběžně při psaní; dovednost pluginu se shoduje i podle samotného názvu bez prefixu pluginu.
  • Ve rozšíření VS Code zobrazí kliknutí na počet agentů v dolní části pole pro prompt mapu agentů, kde lze otevřít přepis subagenta jen pro čtení nebo jej zastavit.
  • Ve rozšíření VS Code přidají položky Hooks a Permissions v sekci Customize příkazového menu háky a pravidla oprávnění přímo do uživatelských, projektových nebo lokálních nastavení.
  • Claude nyní dokáže přiřadit každému publikovanému artefaktu ikonu záložky prohlížeče odpovídající obsahu artefaktu.
  • V Claude Code na webu lze zpětvzít zprávu zařazenou do fronty v cloudovém sezení, než ji Claude přečte — odstraněním z fronty, stiskem Esc nebo šipky nahoru se text vrátí do pole pro zprávu.

Claude Code: strop effortu, hodnocení pluginů a přepínání stylů výstupu

Období Week 37 pokrývá verze v2.1.263 až v2.1.269, tedy sedm buildů, jejichž hlavní linií je tooling kolem pluginů a agentů. Přibyl příkaz pro hodnocení pluginů, přepínač stylů výstupu a konfigurovatelný strop effortu. VS Code získal mapu agentů, podporu hooks a dialogy oprávnění. Průběžně se opravovala také stabilita prompt cache. Zbytek tvoří menší úpravy kolem správy pluginů, telemetrie a práce se sezeními.

Přehled velkých změn

  • Strop úrovně effortu přes maxEffortLevel (v2.1.267)
  • Vyšší limit souběžných agentů v nástroji Workflow (v2.1.269)
  • Hodnocení pluginů příkazem claude plugin eval (v2.1.269)
  • Načtení celé složky pluginů přes --plugin-dir (v2.1.265)
  • Přepínání stylů výstupu příkazem /output-style (v2.1.269)

Velké změny

Strop úrovně effortu přes maxEffortLevel. Nové nastavení maxEffortLevel omezuje úroveň effortu u všech poskytovatelů, včetně Bedrocku, Vertexu a Foundry. Lze ho zadat na nejvyšší úrovni konfigurace, nebo samostatně pro jednotlivé modely v modelSettings. Uživatelé si dál mohou zvolit nižší úroveň, než kolik strop připouští. Interpretace: jde o nástroj pro ty, kdo chtějí mít chování modelu pod kontrolou napříč týmem nebo organizací. Protože nastavení platí u všech poskytovatelů, hodí se zejména tam, kde se Claude Code provozuje přes víc backendů najednou. Dokumentace: Model config. (v2.1.267)

Vyšší limit souběžných agentů v nástroji Workflow. Proměnná CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS (hodnoty 1–256) zvyšuje limit souběžných agentů na jeden běh nástroje Workflow, což je určeno pro větvené úlohy omezené hlavně inferencí. Samostatně /workflows v detailu agenta označuje volání nástrojů jako běžící, selhaná nebo hotová a klávesa Enter rozbalí volání včetně vstupů a výsledků. Interpretace: širší paralelismus přijde vhod u rozsáhlých fan-out úloh, kde čekání na inferenci dominuje nad vším ostatním. Lepší čitelnost detailu pak usnadní zjistit, který z mnoha agentů selhal a proč. Dokumentace: Workflows. (v2.1.269)

Hodnocení pluginů příkazem claude plugin eval. Nový příkaz spustí evaluační sadu pluginu proti Claude Code a vrátí bodované, reprodukovatelné výsledky. Výstup přichází jako JSON a HTML report, možnosti vypíše claude plugin eval --help. Interpretace: autoři pluginů tak získávají měřitelný způsob, jak ověřit kvalitu své práce, a mohou ho zapojit do vlastních procesů. Reprodukovatelnost dává smysl hlavně při porovnávání verzí téhož pluginu. Dokumentace: Plugin evals. (v2.1.269)

Načtení celé složky pluginů přes --plugin-dir. Parametr --plugin-dir nově umí ukázat na složku s více pluginy: načte se každá podsložka, která obsahuje manifest. Podsložky přidané nebo odebrané za běhu Claude Code se zachytí automaticky. Interpretace: vývojáři s více pluginy si ušetří výčet jednotlivých cest a při iteraci nemusejí relaci restartovat. Dokumentace: Načítání pluginů. (v2.1.265)

Přepínání stylů výstupu příkazem /output-style. Nový příkaz /output-style [name] vypíše dostupné styly výstupu a umožní mezi nimi přepínat. Funguje i přes Remote Control a v cloudových či jiných headless sezeních. Interpretace: změna stylu je teď možná i tam, kde není po ruce interaktivní terminál. Jde o komfortní vylepšení, ne o změnu schopností. Dokumentace: Output styles. (v2.1.269)

Drobnosti

  • --system-prompt-snapshot off vykreslí systémový prompt při každém požadavku znovu, což se hodí při ladění textu promptu.
  • Výsledky nástroje Bash mohou obsahovat diff souborů změněných příkazem, pokud je zapnuté nastavení bashEditDiffEnabled.
  • OTEL_METRICS_INCLUDE_REPOSITORY označí metriky a události OpenTelemetry atributy repozitáře vcs.*.
  • Příkazy claude plugin install, uninstall, update, enable a disable mají přepínač --json, řádky claude plugin list --json nově obsahují errorDetails a noteDetails.
  • Instalace, zapnutí či vypnutí pluginu v /plugin se projeví po zavření nabídky, takže /reload-plugins už není potřeba.
  • Lomítkové příkazy zadané uprostřed promptu zobrazují seznam shod a skill z pluginu lze najít podle samotného názvu.
  • Nové spravované nastavení gatewayInternalNetworks umožňuje administrátorům povolit /login k bráně Claude apps na veřejném bloku IPv4 jejich organizace.
  • Při nastaveném pricing: v gateway.yaml dostávají přihlášení klienti stejné sazby, takže /cost a telemetrie odpovídají měřiči nákladů brány.
  • VS Code přidává nastavení „Archive inactive sessions“, které ve výchozím stavu automaticky archivuje sezení neaktivní 14 dní.
  • --continue a --resume zobrazí konverzaci okamžitě, bez čekání na hooks SessionStart.
  • Zamítnutí v auto mode nově jmenují blokující pravidlo a vyzývají Clauda, aby zkusil bezpečnější postup a dokončil nesouvisející práci, než se zastaví a zeptá.
  • Cloudová sezení umožňují vzít zpět zařazenou zprávu dřív, než ji Claude přečte, a to odebráním z fronty nebo klávesou Esc či šipkou nahoru.

Závěr

Week 37 je týden nástrojů pro ty, kdo kolem Claude Code něco staví. Příkaz claude plugin eval, načítání složky pluginů a nové možnosti u workflow agentů míří na autory pluginů a uživatele orchestrace. Strop maxEffortLevel osloví hlavně administrátory, kteří chtějí nastavení sjednotit napříč poskytovateli. Pro každodenní práci jsou nejpraktičtější drobnosti: okamžité zobrazení konverzace po --continue a --resume, žádný /reload-plugins po změně v /plugin a srozumitelnější zamítnutí v auto mode.
