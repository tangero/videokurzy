A publikovaný článek

Omezený režim, pokračování relací a Claudem psané hlášení chyb: novinky Claude Code z 35. týdne

Týden 35 (24.–28. srpna 2026) přinesl do Claude Code tři pojmenované novinky a přes deset drobných vylepšení rozložených napříč CLI, desktopovou aplikací i cloudovými backendy. Charakter vydání je smíšený: jedna změna míří do oblasti bezpečnosti a izolace prostředí, jedna zlepšuje práci s relacemi v desktopové aplikaci a jedna posouvá smyčku zpětné vazby přímo do chatu. Zbytek tvoří vrstva konzistentních kosmetických i výkonnostních úprav — od konfigurace prompt cache přes obnovu přerušených streamů po výrazně menší instalační balíček.

Přehled velkých změn

  • Restricted mode — izolovaný provoz bez nástrojů pro příkazy a kód (v2.1.248)
  • Pokračování CLI relací v desktopové aplikaci příkazem /resume (Desktop)
  • Claude automaticky navrhuje text hlášení chyb nástrojem SendFeedback (CLI)

---

Velké změny

Restricted mode: Claude Code pro sdílená prostředí a evaluační postroje (v2.1.248)

Restricted mode spustí Claude Code bez vestavěných nástrojů, které by mohly spouštět příkazy nebo kód. Konkrétně to znamená: Bash a podobné spouštěče jsou nedostupné, WebFetch je odstraněn, souborové nástroje jsou omezeny výhradně na pracovní adresáře, načítají se pouze spravovaná nastavení a soubory předané přes --settings a režim bypassPermissions je odmítnut. Aktivace je přímočará — přepínač --restricted nebo proměnná prostředí CLAUDE_CODE_RESTRICTED=1.

Restricted mode řeší scénáře, kde evaluační postroj nebo CI pipeline řídí claude na stroji sdíleném s jinými procesy a kde jakákoli náhodná nebo injektovaná instrukce vedoucí ke spuštění kódu představuje riziko. Šlo o chybějící článek pro týmy, které chtějí Claude Code využívat v automatizovaných hodnoceních bez toho, aby musely budovat vlastní sandbox kolem každého volání. Nejde o náhradu sandboxu na úrovni OS, ale o explicitní, auditovatelnou hranici na straně nástroje samotného.

Pokračování CLI relací v desktopové aplikaci (Desktop)

Příkaz /resume v desktopové aplikaci nyní zobrazí seznam všech relací spuštěných z CLI. Každou relaci lze vyhledat podle názvu, složky nebo větve a před navázáním zobrazit náhled, kde konverzace skončila. Po výběru aplikace relaci obnoví se zachovaným celým kontextem a konverzací.

Přemostění mezi CLI a desktopovou aplikací odstraňuje dosud běžný problém: dlouhá relace zahájená v terminálu se nedala pohodlně prohlédnout ani pokračovat v grafickém rozhraní. Funkce ocení vývojáři, kteří střídají prostředí — například zahájí práci v terminálu na serveru nebo v CI smyčce a chtějí ji přezkoumat a rozvinout v aplikaci s plnohodnotným editorem.

Dokumentace: Desktop — příchod z CLI

Claudem navržené hlášení chyb nástrojem SendFeedback (CLI)

Pokud nástroj opakovaně selhává, Claude nemůže s požadavkem pomoci, nebo uživatel upozorní na chybu, Claude nyní sám sestaví návrh hlášení prostřednictvím nástroje SendFeedback. Návrh se zobrazí jako karta nad promptem — uživatel jej může odeslat, upravit nebo zahodit. K Anthropicu nic neodesílá automaticky; odeslání vyžaduje explicitní potvrzení. Funkce vyžaduje verzi v2.1.238 nebo novější.

Jde o posun v ergonomii hlášení problémů. Hlášení chyb bývá nejslabší v okamžiku, kdy uživatel frustrovaný selháním zavře okno a k reportu se nedostane. Tím, že Claude sestrojí kontext sám ve chvíli selhání, klesá tření natolik, že zpětná vazba vzniká přirozeně. Pro Anthropic to zároveň znamená strukturovanější a kontextově bohatší vstupy než volný text.

Dokumentace: Tools reference — chování nástroje SendFeedback

Drobnosti

  • Nastavení modelPicker umožňuje rozšířit nebo nahradit vestavěný seznam příkazu /model vlastními pojmenovanými záznamy, včetně ID modelů z Amazon Bedrock nebo Google Cloud Agent Platform.
  • promptCacheTtl nastavené na 1h udržuje hodinovou prompt cache hlavní konverzace při použití API klíče nebo cloudového poskytovatele; subagentPromptCacheTtl nastavuje TTL pro subagenty a ostatní požadavky mimo hlavní konverzaci.
  • Na plánech Pro, Max, Team a Enterprise přidává /usage přehled Loops: počet spuštění, celkové tokeny, tokeny na spuštění a čas posledního běhu pro /loop a naplánované úlohy s nejvyšší spotřebou.
  • Organizace se smluvními sazbami mohou nastavením modelPricing zajistit, aby /usage, stavový řádek i OpenTelemetry vykazovaly náklady podle jejich sazeb místo ceníkové ceny.
  • /login nově nabízí přihlášení přes Console účet, takže členové Console organizací, které neumožňují API klíče, se mohou přihlásit bez jejich vytváření.
  • Příkaz /permissions zpřístupňuje novou záložku Auto mode, kde lze pravidla klasifikátoru auto mode prohlížet a upravovat bez otevírání souboru nastavení.
  • Výzvy k oprávnění Bash v režimech Manual a acceptEdits nově nabízejí volbu „Ano, a přepnout do auto mode", která příkaz schválí a zároveň relaci přepne do auto mode.
  • Po přesunu relace příkazem /cd se nastavení projektu, hooks, .mcp.json servery, skills a subagenti nového adresáře projeví okamžitě, nikoli až při příštím --resume.
  • V neinteraktivních relacích (běhy -p, Agent SDK, cloudové relace) Claude Code dokončí odpověď přerušenou chybou serveru, výpadkem spojení nebo stálí, pokud přijatá část obsahuje text a žádná volání nástrojů.
  • Subagent, který dosáhne limitu maxTurns, vrátí výstup označený jako neúplný s nápovědou, že Claude jej může nechat pokračovat přes SendMessage, místo aby se zobrazoval jako dokončený.
  • Na Amazon Bedrock, Google Cloud Agent Platform a Microsoft Foundry si relace na stejném stroji nově mohou posílat zprávy, /loop může sám zvolit interval a /model i /effort se projeví okamžitě, nikoli až po dokončení otočky.
  • Nativní instalátor a auto-updater stahují build komprimovaný zstd — přibližně 75 MB místo 340 MB na Linux x64; nativní buildy načítají kód na vyžádání a používají zhruba o 40–70 MB méně paměti na relaci.

Závěr

35. týden byl věcný a technicky vyspělý. Restricted mode je nejdůležitější změnou pro týmy provozující Claude Code v automatizovaných nebo sdílených prostředích — přidává jasně pojmenovanou, auditovatelnou hranici tam, kde dřív bylo potřeba improvizovat. Pokračování CLI relací v desktopové aplikaci ocení vývojáři pohybující se mezi terminálem a grafickým rozhraním, a funkce SendFeedback je nenápadná, ale promyšlená: vzniká ve chvíli frustrace, kdy je zpětná vazba nejcennější. Pod těmito třemi tématy leží solidní vrstva vylepšení spolehlivosti neinteraktivních běhů, konfigurovatelnosti modelů a výkonu instalátoru — dohromady signál, že Claude Code dozrává jako nástroj pro produkční nasazení.

B článek ze changelogu

Claude Code: omezený režim --restricted, jemnější prompt cache a lepší přehled o nákladech

Týden 35 pokrývá verze Claude Code od 2.1.240 do 2.1.250. Neobjevila se žádná zásadní změna principu fungování nástroje. Týden má charakter průběžného ladění a jeho společným jmenovatelem je kontrola. Přibyl uzamčený režim --restricted, panel pro pravidla auto mode, jemnější řízení TTL prompt cache, kurátorský seznam modelů a podrobnější statistiky spotřeby u úloh /loop a subagentů. Doplňuje je řada menších úprav od paměťové náročnosti po přihlašování.

Přehled velkých změn

  • Režim --restricted (v2.1.248)
  • Panel Auto mode v /permissions (v2.1.246)
  • Jemné nastavení TTL prompt cache (v2.1.243)
  • Rozpis úloh /loop v /usage a informace o modelu subagentů (v2.1.243)
  • Vlastní seznam modelů v /model přes modelPicker (v2.1.243)
  • Nástroj SendFeedback (v2.1.247)

Velké změny

Režim --restricted. Příznak --restricted (nebo proměnná CLAUDE_CODE_RESTRICTED=1) odebírá vestavěné nástroje, které spouštějí příkazy nebo kód, a také WebFetch, pokud není výslovně uveden v --tools. Souborové nástroje zůstávají omezené na pracovní adresář, bypassPermissions se odmítá a soubory s nastavením uživatele, projektu i lokálním se ignorují. Interpretace: jde o nejvýznamnější změnu týdne z hlediska bezpečnosti. Ignorování souborů s nastavením znamená, že chování režimu nezávisí na obsahu repozitáře, a to ocení především ti, kdo chtějí Claude Code nasadit v prostředí s omezenou důvěrou. Dokumentace: CLI reference. (v2.1.248)

Panel Auto mode v /permissions. Příkaz /permissions má nový panel Auto mode, v němž lze zobrazit a upravovat pravidla klasifikátoru auto mode. Nové varování při startu navíc upozorní na allow pravidla pro Bash s žolíkem před podpříkazem, například Bash(git main), protože taková pravidla odpovídají i volbám vloženým před podpříkaz. Interpretace:* pravidla auto mode se dosud upravovala hůře dostupnou cestou, takže panel přináší pohodlí a lepší přehled. Varování zachytí příliš široká pravidla, která vypadají přísněji, než ve skutečnosti jsou. Dokumentace: Auto mode config. (v2.1.246)

Jemné nastavení TTL prompt cache. Nová nastavení promptCacheTtl a subagentPromptCacheTtl umožňují uživatelům s API klíčem i cloudovým poskytovatelem držet hodinovou prompt cache v hlavní konverzaci, zatímco subagenti zůstanou na pěti minutách. Frontmatter agenta navíc získal klíč experimental.cacheTtl ("5m" nebo "1h") pro TTL na úrovni jednotlivého agenta, pokud není nastaveno TTL pro subagenty. Interpretace: nákladová páka pro týmy s velkým objemem práce se subagenty. Dlouhá cache se vyplatí tam, kde se kontext opakovaně využívá, krátká stačí u krátkodobých pomocných běhů. Dokumentace: Prompt caching. (v2.1.243)

Rozpis úloh /loop v /usage a informace o modelu subagentů. Příkaz /usage nově obsahuje rozpis po jednotlivých smyčkách: počet běhů, celkový počet tokenů, tokeny na běh a čas posledního běhu. Díky tomu je snadné odhalit úlohy /loop, které se rozběhly nebo jsou nadměrně hovorné. Příkaz /tasks a dialogy s detaily agentů zobrazují také model (a úroveň effort), na kterém konkrétní subagent běžel. Interpretace: k nastavení TTL přibývá i měření. Kdo nechává smyčky běžet delší dobu, získává první pořádný nástroj, jak zjistit, která z nich pálí tokeny. Dokumentace: Costs. (v2.1.243)

Vlastní seznam modelů v /model přes modelPicker. Nové nastavení modelPicker umožňuje definovat seřazený a popsaný seznam modelů pro /model. Přijímá libovolný zápis identifikátoru včetně id pro Vertex a Bedrock. Seznam lze přidat k vestavěné nabídce, nebo ji celou nahradit. Interpretace: změna je užitečná hlavně pro správce týmů a organizací, kteří chtějí vývojářům nabídnout jen schválené modely pod srozumitelnými názvy. Dokumentace: Model config. (v2.1.243)

Nástroj SendFeedback. Když se v relaci něco pokazí, Claude nově připraví návrh zprávy o problému, kterou uživatel zkontroluje a odešle z /feedback. Funkci lze vypnout nastavením feedbackDrafts. Interpretace: jde spíš o komfort než o změnu schopností. Hlášení chyb s kontextem z relace ale může být kvalitnější než zprávy psané zpětně z paměti. Dokumentace: Commands. (v2.1.247)

Drobnosti

  • Přihlášení bez klíče přes /login → Anthropic Console („Sign in with your Console account") umožní vstup organizacím, které API klíče nepovolují.
  • Nové spravované nastavení modelPricing způsobí, že /cost, stavový řádek i telemetrie používají sjednané ceny za model a slevový násobitel organizace místo ceníkových cen.
  • /claude-api cost-optimize zanalyzuje útratu existujícího projektu za Claude API a po jednotlivých změřených krocích projde nákladové páky (caching, hygiena tokenů, batch, effort, volba modelu).
  • Výchozí okno auto-compact u Sonnetu 5 je nově celých 1M kontextu, takže relace s 1M kontextem se kompaktují zhruba při 967 tisících tokenů místo 934 tisíc.
  • /cd nově hned po přesunu uplatní nastavení projektu v novém adresáři, hooks, servery z .mcp.json (s obvyklým potvrzením), skills i agenty, a ne až při --resume.
  • Subagent, který skončí na limitu maxTurns, vrací výstup označený jako částečný, s nápovědou, jak pokračovat přes SendMessage.
  • Neinteraktivní relace (-p, SDK, cloud) automaticky navážou na odpověď přerušenou uprostřed streamu chybou serveru, ztrátou spojení nebo zaseknutím.
  • Nativní buildy spotřebují o zhruba 40–70 MB méně paměti na relaci a nativní binárka se stahuje komprimovaná zstd (na Linuxu x64 asi 75 MB místo 340 MB).
  • Prompt nástroje Workflow se zmenšil z přibližně 5,7 tisíce na přibližně 1 tisíc tokenů, referenci pro psaní skriptů nahradil přibalený skill workflow-authoring.
  • Zasílání zpráv mezi relacemi (SendMessage / ListAgents) funguje na jednom počítači i na Bedrock, Vertex a Foundry a také při vypnuté telemetrii; zprávy od protějšku se sbalí na jednořádkový náhled, který rozbalí Ctrl+O.
  • Samořízený dynamický režim /loop a autonomní výchozí chování bez promptu jsou nově dostupné vždy, i na Bedrock, Vertex a Foundry; po sobě jdoucí nečinná probuzení se sloučí do jednoho řádku.
  • Řádek s délkou tahu na jeho konci nově ukazuje čas dokončení, např. ✻ Sautéed for 23s · done 6:05 PM.
  • /ultrareview <PR#> před spuštěním ověří, že připojený účet GitHub má k repozitáři přístup, a případně vysvětlí nápravu; necommitnuté soubory podobné přihlašovacím údajům, například *.tfvars a key.pem.tmp, se už nenahrávají.

Závěr

Týden 35 nepřinesl žádný efektní skok, ale poctivě rozšiřuje možnosti řízení. Pro bezpečnostně orientované týmy je nejzajímavější režim --restricted spolu s panelem pro pravidla auto mode. Kdo hlídá náklady, ocení jemné TTL prompt cache, rozpis smyček v /usage, modelPricing i /claude-api cost-optimize. Správcům organizací přijde vhod modelPicker a přihlášení bez API klíče. Mezi drobnostmi vyniká zmenšení paměťové stopy nativních buildů a velikosti stahované binárky, které pocítí každý.
