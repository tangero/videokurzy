Verdikt

B je dobrý základ a v rozsahu CLI funkcí i bohatší, ale jako přímá náhrada A nestačí. Chybí Desktop novinka s automatickým pokračováním, je třeba opravit verze a doplnit utnutý závěr.

A je čtivější a má pevnější strukturu (velké změny, drobnosti, závěr), ale většina interpretací je spíš obecná a zčásti nadsazená, třeba „roveň GitHubu“ nebo domyšlené chování týmových agentů. B je u témat, která pokrývá, hlubší a věrnější changelogu (stagger cache, příchozí zprávy, Remote Control, zpřísnění), jeho drobnosti jsou obsáhlé. A publikovaný článek

Fork mode jako výchozí stav a podpora GitLabu: novinky Claude Code z týdne 33

Týden 33 pokrývá vydání v2.1.225 až v2.1.233 a přinesl tři výraznější změny, z nichž každá cílí na jiný aspekt práce: správu kontextu při větvení úloh, paritu mezi GitLabem a GitHubem a komfort při práci s denními limity. Charakter období je spíše zaokrouhlovací než průlomový — žádná změna nepřevrací model práce, ale každá odstraňuje tření, které zkušení uživatelé dobře znají.

Přehled hlavních změn

  • Fork mode zapnutý ve výchozím nastavení (v2.1.232)
  • GitLab merge requesty a tržiště pluginů (v2.1.232)
  • Automatické pokračování po vypršení limitu relace v desktopové aplikaci (Desktop)

---

Velké změny

Fork mode zapnutý ve výchozím nastavení

Od v2.1.232 se fork mode aktivuje automaticky v každé interaktivní relaci. Subagent typu fork nespouští prázdnou konverzaci, ale přebírá celou historii a prompt cache volající relace. Vedlejší úlohu tak lze zadat bez opakovaného vysvětlování kontextu, který Claude v hlavní větvi již zná. Subagenti spouštění přímo interaktivní relací — nikoli spoluhráčem v týmu agentů — navíc nyní běží na pozadí jako výchozí chování.

Interpretace: Změna nejvíce pomůže těm, kdo rozčleňují složité úlohy do paralelních dílčích kroků. Dosud bylo ruční zapnutí fork mode nutnou administrativou; nyní se kontextová kontinuita stává základním stavem. Pozor — subagenti spuštění jiným agentem v rámci týmu sdílené chování nezdědí, takže chování vícestupňových pipeline se nezmění automaticky.

Dokumentace: Sub-agents – Fork mode (v2.1.232)

---

GitLab merge requesty a tržiště pluginů

GitLab se v této verzi dostává na srovnatelnou úroveň s GitHubem hned v několika rovinách. Tržiště pluginů nyní správně klonují holé adresy URL z gitlab.com včetně vnořených podskupin. Od v2.1.233 lze předat URL GitLab merge requestu přepínači --worktree a Claude Code z něj vytvoří větev; zobrazení claude agents označuje relace svázané s merge requestem jako !N. Bezpečnostní stránka nechybí: Claude Code maskuje rodiny tokenů jako glpat- a glrt- a chrání konfigurační úložiště nástroje glab stejným způsobem, jakým dosud chránil gh.

Interpretace: Pro týmy pracující výhradně nebo souběžně v GitLabu jde o zásadní praktický krok — doposud chyběla nativní integrace na úrovni, která existovala pro GitHub. Maskování tokenů a ochrana konfigurace glab jsou tichým, ale důležitým bezpečnostním doplněním; projekty s CI/CD přes GitLab přestávají být vůči únikům citlivých údajů v nevýhodě.

Dokumentace: Worktrees – Branch from a pull/merge request (v2.1.232)

---

Automatické pokračování po vypršení limitu relace v desktopové aplikaci

Narazíte-li na limit relace v záložce Code desktopové aplikace, zobrazí se nová možnost: zaškrtávací políčko „Automaticky pokračovat po resetování limitu". Po zaškrtnutí aplikace sama zopakuje přerušenou akci v době resetu, kterou karta rovnou zobrazí. Týdenní limit tuto možnost nenabízí.

Interpretace: Drobná UX změna s výrazným dopadem na dlouho běžící automatizované relace — přerušení limitu přestává vyžadovat ruční dohled. Limit týdenní zůstává mimo dosah automatiky, což má zřejmě důvody na straně cenových plánů; uživatelé provozující náročné nočními dávkové úlohy si tuto hranici musí hlídat sami.

Dokumentace: Errors – Session limit (Desktop)

---

Drobnosti

  • Zadáním @ v promptu lze zmínit jinou relaci Claude jménem a Claude jí přímo odešle zprávu přes SendMessage; pokud jméno jednoznačně odpovídá jedné živé relaci, potvrzovací krok odpadá
  • Unikátní názvy relací: pojmenujete-li relaci stejně jako jiná živá relace, Claude Code automaticky vygeneruje variantu ve tvaru název-slovo-slovo a uživatele o tom informuje
  • Tržiště pluginů nově podporují zdroje příkazů: lokální příkaz vypíše adresář pluginu, který Claude Code při každém spuštění relace znovu vyhodnotí a aplikuje bez restartu
  • Na Linuxu a v prostředí WSL lze proměnnou CLAUDE_CODE_TOOL_MEMORY_LIMIT (například 4G) omezit paměť dostupnou příkazům nástroje Bash a PowerShell
  • Nástroje pro sledování úloh (TaskCreate, TaskUpdate, TodoWrite a podobné) nejsou nadále dostupné na modelech Opus 4.8, Sonnet 5, Fable 5, Mythos 5 a novějších v těchto rodinách; proměnná CLAUDE_CODE_ENABLE_TODO_TOOLS=1 je vrátí zpět
  • /code-review na úrovních high, xhigh a max nyní běží v agentovi na pozadí stejně jako ostatní úrovně
  • /plugin install plugin@marketplace před instalací automaticky aktualizuje tržiště, takže nově publikované pluginy nevyžadují ruční obnovení
  • Nastavení přijímají additionalMarketplaces a allowedMarketplaces jako aliasy pro extraKnownMarketplaces a strictKnownMarketplaces
  • Na novějších modelech Claude dokáže přepsat existující soubor nástrojem Write bez předchozího čtení v aktuální relaci — stejná pravidla jako u nástroje Edit; starší modely čtení stále vyžadují
  • Rozšíření pro VS Code umožňuje uspořádat seznam relací do skupin: pravým tlačítkem skupinu vytvoříte, přejmenujete nebo smažete, kombinací Cmd/Ctrl nebo Shift s kliknutím přesunete více relací najednou
  • Pokud vaše organizace provozuje Claude Code přes bránu Claude apps s limity útraty, Claude Code při dosažení limitu zobrazí období limitu, čas jeho resetování a zprávu operátora

Týden 33 je charakteristický scelováním — GitLab dorovnává GitHub, fork mode přestává být volitelnou funkcí a stává se základem, desktopová aplikace přebírá rutinní dohled po resetování limitu. Pro týmy s GitLabem ve workflow jde o nejvýznamnější moment tohoto vydání; pro ostatní je nejzajímavější změnou výchozí fork mode, který prospěje každému, kdo práci dělí do paralelních větví. Drobností přibylo mnoho — žádná sama o sobě nepřevrací pracovní postup, ale dohromady snižují počet situací, kdy je třeba sahat mimo Claude Code.

B článek ze changelogu

Claude Code: relace si píšou mezi sebou, subagenti dědí kontext a marketplace se otevírá GitLabu

Týden 33 přinesl devět verzí Claude Code, od v2.1.225 do v2.1.233. Hlavní linií je komunikace mezi relacemi: jiné relace Claude lze oslovit přes @ a zprávy putují i mezi stroji. Druhou linií je rozšíření marketplaců pluginů o příkazové zdroje a podporu GitLabu. Třetí tvoří řada zpřísnění kolem sandboxu, oprávnění a maskování tajných údajů. K tomu se mění výchozí chování subagentů a sada nástrojů na nejnovějších modelech.

  • Oslovení jiných relací Claude přes @-zmínky a SendMessage (v2.1.232)
  • Nastavení příchozích zpráv z jiných relací v /config (v2.1.232)
  • Forkování subagentů zapnuté ve výchozím stavu (v2.1.232)
  • Odebrání nástrojů pro správu úkolů na nejnovějších modelech a uvolnění nástroje Write (v2.1.233)
  • Marketplacy pluginů: příkazové zdroje a podpora GitLabu (v2.1.229)
  • Skupiny relací v postranním panelu VS Code (v2.1.229)

Oslovení jiných relací Claude přes @-zmínky a SendMessage. V promptu stačí napsat @ a jméno jiné relace Claude, Claude ji pak osloví přímo přes SendMessage. Nástroj SendMessage nově doručí zprávu na holé jméno, které přesně odpovídá jedné živé relaci. Interaktivní relace na jednom stroji mají unikátní jména, a pokud je jméno obsazené, vznikne varianta ve tvaru name-word-word. Od verze v2.1.225 umí SendMessage podle jména zahájit konverzaci také s vašimi relacemi Remote Control na jiných strojích. Interpretace: souběžně běžící relace se tím mění z izolovaných ostrůvků v adresovatelné účastníky. Nejvíc si polepší ten, kdo drží rozpracované úlohy na více strojích a dosud je musel propojovat ručně. Dokumentace: Cross-session messaging. (v2.1.232)

Nastavení příchozích zpráv z jiných relací v /config. Nabídka /config získala řádek „Messages from your other sessions“, kde lze příchozí zprávy z jiných relací přijímat, podržet, nebo odmítat. Přibyl i řádek „Dialog expiry“. Zprávy mezi relacemi navíc od v2.1.228 ukazují odesílatele a text přímo v řádku, místo aby byly sbalené do jediné řádky. Interpretace: jakmile mohou relace psát jedna druhé, potřebuje uživatel pojistku, která řídí, co do jeho relace smí doputovat. Tohle nastavení ji dodává a zároveň zlepšuje čitelnost toho, kdo co poslal. Dokumentace: Cross-session messaging. (v2.1.232)

Forkování subagentů zapnuté ve výchozím stavu. Subagent se subagent_type: "fork" nyní zdědí celou konverzaci i prompt cache. Spouštění agentů, kteří nejsou teammate, běží v interaktivních relacích ve výchozím stavu na pozadí. Paralelní rozvětvení workflow navíc zpožďují souběžné sesterské agenty se shodným prefixem, takže pozdější z nich čtou prefix promptu z cache a neplatí ho znovu. Interpretace: kdo rozděluje práci mezi několik subagentů nad společným kontextem, může počítat s nižšími náklady na opakované zpracování téhož prefixu. Běh na pozadí zase mění rytmus práce, protože hlavní relace nečeká na každého spuštěného agenta. Dokumentace: Subagenti. (v2.1.232)

Odebrání nástrojů pro správu úkolů na nejnovějších modelech a uvolnění nástroje Write. Nástroje pro sledování úkolů (TaskCreate, TaskGet, TaskUpdate, TaskList a TodoWrite) už nejsou dostupné na modelech Opus 4.8, Sonnet 5, Fable 5, Mythos 5 a novějších. Vrátí je nastavení CLAUDE_CODE_ENABLE_TODO_TOOLS=1. Nástroj Write dále umožňuje novějším modelům přepsat existující soubor, který v dané relaci nečetly, v souladu s pravidly nástroje Edit. Interpretace: kdo má v promptech, skriptech nebo vlastních workflow vazbu na tyto nástroje, měl by změnu otestovat, proměnná prostředí slouží jako záchranná cesta. Uvolněné Write lze číst jako sjednocení pravidel obou zapisovacích nástrojů. Dokumentace: Tools reference. (v2.1.233)

Marketplacy pluginů: příkazové zdroje a podpora GitLabu. Marketplacy pluginů mohou používat zdroje typu command. Lokální příkaz, například z IDE, vypíše adresář pluginu, ten se při každé relaci znovu vyhodnotí a použije bez restartu. S mode: "link" se plugin používá přímo na místě. Od v2.1.232 se holé URL repozitářů z gitlab.com, včetně vnořených podskupin, klonují stejně jako URL z github.com. /plugin install plugin@marketplace také nejprve obnoví daný marketplace. Interpretace: příkazové zdroje zkracují cestu mezi vývojem pluginu v IDE a jeho vyzkoušením v Claude Code. Týmy hostující kód na GitLabu se přestávají cítit jako druhá kategorie. Dokumentace: Plugins. (v2.1.229)

Skupiny relací v postranním panelu VS Code. Postranní panel ve VS Code nově podporuje skupiny relací. Pravým tlačítkem je možné skupinu vytvořit, přejmenovat nebo smazat, a kliknutím s Cmd/Ctrl nebo Shiftem lze přesouvat více relací najednou. Interpretace: jde o komfortní změnu, která oceníte až s růstem počtu relací. Přichází v týdnu, kdy se relace díky vzájemné komunikaci množí. Dokumentace: VS Code. (v2.1.229)

Drobnosti: - Upozornění na využití podporuje limity útraty na gateway: zpráva o dosažení limitu uvádí strop, čas obnovení a zprávu operátora (vyžaduje gateway ve verzi 2.1.225). - claude agents nově zobrazuje pro nedůvěryhodné adresáře výzvu k potvrzení důvěry v pracovní prostor, stejně jako claude. - Fotografie přiložené z aplikace Claude přes Remote Control se nově ukazují Claudovi přímo, bez čtení z disku samostatným voláním nástroje. - Fable 5 je opět nabízen jako advisor v /advisor pro organizace s přístupem k Fable. - URL merge requestů z GitLabu fungují s --worktree i v zobrazení claude agents, kde se MR zobrazují jako !N. - Volitelná proměnná CLAUDE_CODE_TOOL_MEMORY_LIMIT přidává na Linuxu paměťovou cgroup pro příkazy nástroje Bash, takže splašený build nezablokuje relaci. - Nová proměnná CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS nastavuje TTL relační URL cache nástroje WebFetch (výchozí hodnota zůstává 15 minut). - Remote Control se po výpadku sítě snaží znovu připojit zhruba 30 minut a terminál hlásí, zda byla relace převzata, ukončena jinde, nebo smazána. - Průběh komprimace nově ukazuje odpočet opakování a nápovědu při zaseknutí a chyby „prompt is too long“ vysvětlují, proč automatická komprimace nepomohla. - Maskování tajných údajů pokrývá rodiny tokenů GitLabu a konfigurační úložiště CLI glab má stejnou ochranu sandboxu a cest k přihlašovacím údajům jako gh. - Chybějící nebo prošlé přihlašovací údaje Google Cloud na Vertex AI nyní selžou během vteřin, místo aby se minuty opakovaly. - Panel vedlejších otázek /btw ve VS Code lze zvětšovat a zmenšovat tažením za hranici. - /code-review na úrovních high, xhigh a max nově běží v agentovi na pozadí jako ostatní úrovně.

Celkově je to týden, ve kterém se Claude Code učí pracovat s více relacemi a agenty najednou, a zároveň k tomu přidává kontrolní prvky. Nejzajímavější je to pro uživatele, kteří provozují několik souběžných relací nebo subagentů: ti získají adresné zprávy mezi relacemi, nastavení příchozí komunikace a levnější sdílení kontextu díky cache. Týmy na GitLabu ocení marketplacy a podporu merge requestů, autoři pluginů příkazové zdroje. Vývojáři postavení na nástrojích pro správu úkolů
