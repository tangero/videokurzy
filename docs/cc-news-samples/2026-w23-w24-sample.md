# Claude Code za poslední dva týdny: vnořené subagenty, bezpečnější editace a ladicí režim

Za první dva červnové týdny vyšlo v Claude Code jedenáct verzí, od v2.1.158 po v2.1.176. Žádná z nich není velký release. Jde o inkrementální změny, a když je seřadíte podle váhy, vykrystalizují dvě linie: utahování bezpečnostních a provozních šroubů na jedné straně a jediné reálné rozšíření schopností v podobě hlubší orchestrace subagentů na straně druhé.

Přehled velkých změn:

- **Subagenti mohou spouštět vlastní subagenty** — vnořené stromy se stropem pět úrovní (v2.1.172).
- **Bezpečnější automatické editace** — i v režimu `acceptEdits` se Claude Code ptá před zápisem do spustitelných konfiguráků (v2.1.160).
- **Auto mode na Bedrock, Vertex a Foundry** — pro Opus 4.7 a Opus 4.8 (v2.1.158).
- **Safe mode** — spuštění bez všech customizací pro ladění rozbité konfigurace (v2.1.169).
- **Příkaz `/cd`** — přesun sezení do jiného adresáře se zachováním prompt cache (v2.1.169).
- **Verzové požadavky pro řízená nasazení** — `requiredMinimumVersion` a `requiredMaximumVersion` (v2.1.163).

## Velké změny

**Subagenti mohou spouštět vlastní subagenty.** Subagent nově může zadat práci dalším subagentům a vytvořit tak vnořený strom. Panel pod promptem zobrazuje celý strom: u každého řádku je počet potomků a cesta zpět k hlavnímu sezení. Hloubka zanoření je zastropována na pět úrovní jako pojistka proti rozběhnutým souběžným větvím a s nimi spojeným nákladům. Tohle je jediná položka z obou týdnů, která rozšiřuje, co nástroj umí, ne jen jak se chová. Detaily v [dokumentaci k subagentům](https://code.claude.com/docs/en/sub-agents#spawn-nested-subagents). (v2.1.172)

**Bezpečnější automatické editace.** Claude Code se nově ptá na svolení před zápisem do souborů, které umějí spustit kód, a to i v režimu `acceptEdits`, kde jinak změny schvaluje automaticky. Chráněná množina pokrývá startovací soubory shellu jako `.zshenv` a `.bash_login`, git konfiguraci pod `~/.config/git/` a konfiguráky build nástrojů jako `.npmrc`, `.bazelrc` nebo `.pre-commit-config.yaml`. Tyto zápisy se neschválí automaticky v žádném režimu kromě `bypassPermissions`. Jde o věcnou obranu proti scénáři, kdy by si agent přepsal konfiguraci, která se vzápětí sama spustí. Viz [chráněné cesty](https://code.claude.com/docs/en/permission-modes#protected-paths). (v2.1.160)

**Auto mode na Bedrock, Vertex a Foundry.** Auto mode je nově dostupný i u tří poskytovatelů třetích stran — AWS Bedrock, Google Vertex a Microsoft Foundry — pro modely Opus 4.7 a Opus 4.8. Místo dotazů na oprávnění tu nastupují bezpečnostní kontroly na pozadí. Zapíná se proměnnou prostředí `CLAUDE_CODE_ENABLE_AUTO_MODE=1`. Relevance je hlavně podniková, protože velké organizace běžně provozují Claude přes vlastní cloudovou infrastrukturu. [Zapnutí auto mode u poskytovatelů třetích stran](https://code.claude.com/docs/en/permission-modes#enable-auto-mode-on-bedrock-vertex-ai-or-foundry). (v2.1.158)

**Safe mode pro ladění.** Spuštění přes `claude --safe-mode` nebo proměnnou `CLAUDE_CODE_SAFE_MODE` nastartuje prostředí s vypnutými všemi customizacemi: nenačte se `CLAUDE.md`, skills, pluginy, hooks, MCP servery ani vlastní příkazy a agenti. Autentizace, výběr modelu, vestavěné nástroje a oprávnění fungují dál. Logika je přímočará — když problém v safe mode zmizí, viník je v jedné z vypnutých vrstev. Ladicí primitiv, který v nástroji s takovým množstvím konfiguračních vrstev dává smysl. [Test proti čisté konfiguraci](https://code.claude.com/docs/en/debug-your-config#test-against-a-clean-configuration). (v2.1.169)

**Příkaz /cd přesune sezení do jiného adresáře.** Nový příkaz `/cd` přemístí běžící sezení do jiného pracovního adresáře a zachová přitom prompt cache. Místo přepsání systémového promptu se `CLAUDE.md` nového adresáře připojí jako zpráva. Sezení se přestěhuje do úložiště nového projektu, takže ho `--resume` a `--continue` najdou tam. U dosud nepoužitého adresáře si Claude Code vyžádá potvrzení důvěry. Inženýrský detail, který šetří tokeny i latenci tím, že se cache nemusí stavět znovu. [Reference příkazů](https://code.claude.com/docs/en/commands#all-commands). (v2.1.169)

**Verzové požadavky pro řízená nasazení.** Dvě řízená nastavení, `requiredMinimumVersion` a `requiredMaximumVersion`, umožňují organizaci vynutit schválené rozmezí verzí Claude Code. Klient mimo rozmezí se při startu ukončí a vyzve uživatele k aktualizaci. Příkazy `claude update`, `claude install` a `claude doctor` fungují dál, takže uživatel má jak se z vynuceného zastavení dostat. [Co vynucovat](https://code.claude.com/docs/en/admin-setup#decide-what-to-enforce). (v2.1.163)

## Drobnosti

Zbytek jsou provozní úpravy a kosmetika, každá na jeden řádek:

- `fallbackModel` nastaví řetězec až tří záložních modelů, které se zkouší popořadě, když je primární přetížený; `--fallback-model` nově platí i pro interaktivní sezení.
- Výpisy `claude mcp` (list, get, add) už netisknou tajemství — reference na proměnné prostředí se nerozbalují a přihlašovací hlavičky i tajemství v URL jsou redigovány.
- Zprávy přeposlané mezi sezeními přes `SendMessage` už nenesou uživatelskou autoritu a auto mode je blokuje.
- Amazon Bedrock přečte AWS region z konfigurace v `~/.aws`, když není nastavená proměnná `AWS_REGION`; `/status` ukáže, odkud se region vzal.
- Nové nastavení `enforceAvailableModels` rozšíří seznam povolených modelů i na výchozí model.
- `/plugin list` vypíše nainstalované pluginy bez otevírání menu; v menu `/plugin` přibyla vyhledávací lišta.
- Klíčové slovo pro dynamické workflow se změnilo z `workflow` na `ultracode`.
- Hooks typu Stop a SubagentStop mohou vrátit `additionalContext` a nechat tah pokračovat místo ukončení chybou.
- Selhání jednoho příkazu Bash v paralelní dávce už neruší ostatní; každý nástroj vrátí vlastní výsledek.
- Názvy sezení se generují v jazyce konverzace; konkrétní jazyk lze připnout nastavením `language`.
- Windsurf je v `/ide`, `/terminal-setup` a `/scroll-speed` přejmenován na Devin Desktop, v návaznosti na akvizici tohoto editoru společností Cognition a jeho rebranding.
- Drobnosti navrch: `claude update` oznámí cílovou verzi před stažením, `/btw` má zkratku `c` pro zkopírování odpovědi, přibylo nastavení `footerLinksRegexes` a `disableBundledSkills` a hodnoty `OTEL_RESOURCE_ATTRIBUTES` se připojují jako popisky k metrikám.

Souhrnně: dva týdny bez velkého oznámení. Polovina obsahu je bezpečnostní a provozní hardening, jedna položka reálně přidává schopnost. Pro řízená podniková nasazení jsou nejzajímavější verzové zámky a auto mode u poskytovatelů třetích stran, pro běžnou práci u terminálu pak vnořené subagenty a ochrana spustitelných konfiguráků.
